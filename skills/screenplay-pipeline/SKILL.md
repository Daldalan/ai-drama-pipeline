"각본"이라는 단어가 없어도 줄거리를 설명하며 이야기를 만들어달라는 맥락이면 사용한다.

# Screenplay Pipeline (한국어 각본 제작 파이프라인)

스토리 피치 하나를 받아 **캐릭터 → 세계관 규칙 → 트리트먼트 → 파트 분할 → 씬별 대본 → 재미 점검 → Word → 통합본**까지 뽑는 워크플로우.
모든 산출물은 사용자의 프로젝트 폴더(없으면 물어보지 말고 작품명으로 된 폴더)에 저장하고,
md가 원본(마스터), docx는 md에서 변환한 전달용이다. 수정은 항상 md에 하고 docx를 재생성한다.

단계는 전부 필수가 아니다. 사용자가 이미 가진 것(캐릭터·설정·줄거리)은 건너뛰고, 요청한 단계부터 시작한다.
점검만 요청하면("이 줄거리 점검해 줘", "재미 포인트 봐 줘") 해당 점검 단계만 수행한다.

## 산출물 구조

단편·부(部) 구성 작품:
```
<작품폴더>/
├── 캐릭터_카드.md             # 단계 0
├── <작품명>_바이블.md          # 단계 0.5 (연재·시리즈일 때)
├── 1부_트리트먼트.md          # 단계 1 (+ 파트 분할 표, 단계 1.5)
├── 1부_대본.md / .docx        # 단계 2~3 (부가 늘면 2부_, 3부_...)
├── 디즈니요소_체크리스트.md    # 단계 4 (원작 IP가 있을 때)
└── <작품명>_통합본.md / .docx  # 단계 6 (완결 시)
```

에피소드 연재물(영상 제작까지 이어질 때)은 사용자가 원하면 에피소드 폴더로 나눈다:
```
EP05_<부제>/
├── 01_story     # 트리트먼트·파트 분할·대본 (이 스킬의 산출물)
├── 02_sheets    # 캐릭터 시트 (의상별)
├── 03_assets    # 배경·소품
├── 04_prompts   # 파트별 영상 프롬프트
├── 05_clips / 06_sound / 07_edit
```
파트·컷 이름 규칙: `EP05_P2_CUT3_V2` (에피소드_파트_컷_버전). 파트 분할 표의 파트 번호를 이 규칙과 맞춘다.

## 설계 원칙 — 크게 짜고, 작게 만든다

AI 영상은 한 번에 생성할 수 있는 길이(클립)가 짧다. 그래서:
- **기획은 큰 단위부터**: 시리즈 → 에피소드 → 편(숏츠/부) → 파트(클립)
- **제작은 작은 단위부터**: 클립 → 편 → 에피소드 → 모아보기
- 배포를 염두에 두면 같은 영상이 세 형태로 재사용된다: **숏츠(편, 플랫폼 상한 약 3분) → 에피소드(10~20분) → 모아보기(60분+)**. 사용자가 이 구조를 쓰면 편 단위로 끊기는 지점(편 끝 훅)을 처음부터 설계한다.
- 길이는 억지로 맞추지 않는다. 이야기 전달이 우선이고, 길이는 편집에서 다듬는다. 편 상한은 플랫폼 제약일 뿐 목표 분량이 아니다.
- 파트(클립) 길이는 프로젝트 지침의 기본 단위(예: 15초)를 따르되, 사용하는 영상 도구의 최대 길이(예: Seedance 30초) 안에서 장면에 맞게 조절한다.

## 단계 0 — 캐릭터 카드 (캐릭터가 먼저)

이야기보다 캐릭터를 먼저 세운다. 캐릭터가 서 있으면 장면마다 "이 인물이라면 어떻게 할까"로 판단이 쉬워진다.
1. **쾌감부터 정한다** — 시청자가 보고 싶어 하는 장면(참교육·사이다, 개그, 성장, 로맨스 등).
2. **쾌감 축마다 한 명씩** — 주인공이 여럿이면 축이 겹치지 않게(예: 힘·외모·돈).
3. **카드를 채운다** — 이름·나이·능력·성격·말투·**트레이드마크 동작**(반복되는 동작·대사 하나).
4. **얼굴은 현실적으로** — 지나치게 미화되지 않은, 있을 법한 얼굴로 묘사한다(이후 캐릭터 시트 프롬프트의 기준).
표 형식 템플릿: `references/templates.md`의 "캐릭터 카드 템플릿". 깊은 인물 인터뷰가 필요하면 `character-builder` 스킬과 함께 쓴다.

## 단계 0.5 — 세계관 규칙 + 시리즈 바이블

줄거리 전에 **세계관 규칙**을 먼저 정한다: 능력의 대가, 조직, 금기.
규칙이 있어야 장면마다 판단이 흔들리지 않는다(예: "능력이 자기 수명을 깎는다 → 가벼운 장면에서는 쓰지 않는다").

연재·시리즈 작품이면 **바이블**(`<작품명>_바이블.md`, 사용자가 노션을 쓰면 노션에 옮길 수 있는 형태)을 유지한다:
- **확정된 설정만** 적는다. 아직 정하지 않은 건 `(보류)`로 표시한다.
- 바뀐 설정은 **날짜와 함께 갱신 기록**을 남긴다(덮어쓰지 않는다).
- **떡밥·반전 목록**과 회수 예정 아크/에피소드를 함께 적는다.
- 새 트리트먼트·대본을 쓸 때마다 바이블과 충돌하는지 먼저 확인한다.
템플릿: `references/templates.md`의 "시리즈 바이블 템플릿".

## 단계 1 — 트리트먼트

사용자의 피치를 뼈대로 삼되, 비어 있는 조각(작품 속 고유명사, 계기 사건, 개그 포인트)은
직접 창작해서 채운다. 채운 부분은 답변에서 "내가 짠 부분"으로 명시해 사용자가 거부권을 행사할 수 있게 한다.
구성: 로그라인 → 세계관/네이밍(이름에는 주제와 연결된 이유를 붙인다) → **편의 톤·연출 기준** → 씬 구성(S1, S2...) → **5요소 점검** → **심어둔 떡밥** 섹션.

- **한 편 단위로 기획한다.** 연재물이라도 편마다 독립된 사건(목표와 결말)을 갖게 한다.
- **5요소 점검**: 편마다 **목표 → 장애 → 전술 → 반전 → 관객 평가 변화**가 서 있는지 진단한다. 빈 요소, 약한 요소, 기존 설정(바이블)과 충돌하는 부분을 함께 보고한다. "관객 평가 변화"는 이 편이 끝났을 때 관객이 인물·상황을 다르게 보게 되는 지점이다.
- **톤·연출 기준**: 편의 톤을 한 단어(긴박함·코믹·감동 등)로 정하고, 사용자가 원하면 그 톤에 맞는 레퍼런스 감독/촬영감독 기준을 함께 적는다. 이 기준은 이후 이미지·영상 프롬프트가 한 편 안에서 같은 룩을 유지하도록 넘겨주는 값이다(한 편 안에서 섞지 않는다).
- 떡밥 섹션이 중요한 이유: 다음 부(部)를 쓸 때 회수 목록이 되고, 통합본의 "떡밥 회수표" 부록이 된다.
상세 템플릿: `references/templates.md`의 "트리트먼트 템플릿".

## 단계 1.5 — 파트 분할 (클립 단위)

영상으로 만들 작품이면 트리트먼트(또는 대본)를 **클립 하나로 생성 가능한 길이의 파트**로 나눈다.
파트마다 적는 것: **장소 · 등장인물 · 핵심 대사 · 마지막 훅**(+ 예상 길이).
- 파트 끝은 다음 파트가 궁금하게 끊는다(훅). 편의 마지막 파트는 다음 편으로 넘어가는 훅.
- 한 파트에 대사·동작·감정을 과하게 넣지 않는다. 대사가 길이를 넘기면 속도를 높이지 말고 파트를 나눈다.
- 액션이 있는 파트는 한 합을 **준비 → 타격 → 반응 → 여운** 비트로 적어 둔다(영상 단계에서 3~4컷으로 쪼개기 쉽게).
- 같은 장소가 이어지는 파트는 인물 위치·방향·문/소품 상태를 파트 시작에 적어 다음 파트로 이어받게 한다.
템플릿: `references/templates.md`의 "파트 분할 표".

## 단계 2 — 씬별 대본

트리트먼트의 씬을 대사가 들어간 대본으로 확장한다. **부가 이어지면 씬 번호도 이어서**(1부가 S#9에서 끝나면 2부는 S#10부터).

마크다운 포맷은 변환 스크립트가 파싱하므로 아래 문법을 정확히 지킨다:

| 요소 | 문법 | Word 렌더링 |
|------|------|------------|
| 문서 제목 | `# 제목` | 표지 타이틀 (두 번째 `#`부터는 새 페이지) |
| 씬 헤딩 | `## S#1. 장소 (시간)` | 남색 헤딩 + 밑줄 |
| 대사 | `**이름:** (지시문) 대사` | 인물명 볼드 + 들여쓰기 |
| 지문 | 일반 텍스트 줄 | 회색 이탤릭 |
| 몽타주 헤딩 | `### [몽타주 — 제목]` | 보라색 볼드 |
| 몽타주 항목 | `- 항목` | 불릿 |
| 부 종료 | `**— 1부 끝 —**` | 가운데 정렬 |
| 구분선 | `---` | 회색 가로선 |

작법 원칙:
- 내레이션·조연도 캐릭터다. 주인공이 원작/규칙을 부수는 이야기라면 내레이션이 무너지는 리액션 자체가 러닝 개그가 된다.
- 캐릭터 카드의 말투와 트레이드마크 동작을 대사·지문에 반복해서 살린다.
- 화면 속 글자(간판·문자 메시지 등)가 필요한 장면은 지문에 "자막/편집 삽입"으로 표시한다. 영상 생성 도구는 한글 글자를 깨뜨리기 쉽다.
- 각 부 끝에 "심어둔 떡밥 (다음 부용)" 섹션을 붙인다 — **반드시 `**— N부 끝 —**` 마커 뒤에**. 통합본의 awk 추출(단계 6)이 이 마커에서 멈추므로, 마커 앞에 쓰면 작업 노트가 통합본에 딸려 들어간다. 다음 부는 이 목록을 회수하며 시작한다.
- 1부에서 심은 소품·표정·대사는 마지막 부에서 의미가 뒤집힌 채 돌아오게 한다(콜백 대칭).

## 단계 2.5 — 재미 포인트 점검 (편마다)

에피소드 구성이 끝나면 편마다 **개그 · 감동 · 반전 · 공감 · 참교육(사이다)** 다섯 가지가 있는지 점검한다.
설명과 떡밥만 있는 편일수록 이 다섯이 비기 쉽다. 작품 장르에 따라 축은 바꿀 수 있다(예: 참교육 대신 설렘).
1. 편마다 다섯 축의 유무를 표로 보여 준다.
2. 비어 있는 편, 늘어지는 구간을 짚는다.
3. **구간마다 포인트를 3~5안** 제안한다. 각 안은 한두 줄, 캐릭터·세계관 근거를 붙인다.
4. **작가가 고른다.** 임의로 대본에 넣지 않는다.
5. 고른 안을 넣은 뒤 설정 충돌(바이블·캐릭터 카드)까지 다시 점검한다.
템플릿: `references/templates.md`의 "재미 포인트 점검표".

## 단계 3 — 밈 패러디 (요청 시)

한국 유명 밈을 개그로 넣어달라고 하면: **짤 이미지 삽입은 금지**(방송사 저작권+초상권),
**대사·상황 패러디로만** 녹인다. 원칙과 검증된 밈 목록: `references/templates.md`의 "밈 패러디 가이드".
개수는 부당 4~6개로 절제하고, 캐릭터 일관성에 맞는 자리에만 배치한다(밈을 위해 장면을 만들지 말 것).

## 단계 4 — IP 체크리스트 (원작이 있는 작품일 때)

동화·고전 등 원작 기반 작품이면 `디즈니요소_체크리스트.md`류 파일을 만들어 유지한다.
핵심 원칙: **원작(퍼블릭 도메인)은 자유, 각색자(디즈니 등)가 추가한 표현은 금지.**
골격: `references/templates.md`의 "IP 체크리스트 템플릿". 새 부를 쓸 때마다 이 기준으로 자체 검열한다.

# 변환 (NODE_PATH로 docx 모듈 위치 지정)
NODE_PATH=<스크래치패드>/node_modules node \

## 단계 6 — 통합본 (완결 시)

여러 부를 하나로 묶을 때:
1. **통합 헤더**를 새로 쓴다: 로그라인 / 전체 등장인물(정체 공개 반영) / 세계 규칙 통합 / 배경.
2. 각 부 md에서 씬 구간만 추출해 `# 제N부 — 부제` 헤딩 아래 붙인다:
   ```bash
   awk '/^## S#/{f=1} f{print} f && /^\*\*— .+ —\*\*$/{exit}' <N부_대본.md>
   ```
   (각 부의 개별 등장인물 블록과 "심어둔 떡밥" 작업 노트는 통합본에서 제외된다 — 의도된 것)
3. 끝에 **부록 — 떡밥 회수표**를 붙인다: 각 떡밥의 "심음: 씬번호 → 회수: 씬번호" 매핑. 수정 시 떡밥이 끊기는 사고를 막는 안전망이다.
4. 단계 5로 docx 변환. `#` 제목이 여러 개면 스크립트가 자동으로 부마다 새 페이지를 시작한다.

## 단계 7 — 영상 프롬프트 (선택)

완성된 씬을 영상으로 만들고 싶다는 요청이 오면: 프롬프트 텍스트만 필요하면 `seedance-cut-prompt` 스킬, 실제 영상 제작(캐릭터 시트→Element→렌더→조립)까지면 `ai-character-drama` 스킬로 넘어간다.
넘길 때 단계 1.5의 파트 분할 표와 단계 1의 톤·연출 기준을 함께 전달한다.

## 진행 원칙

- 각 단계 산출물을 낸 뒤 사용자 피드백을 받고 다음 단계로 간다. 단, 사용자가 "N부도 써줘"처럼 명확히 요청하면 바로 진행.
- 사용자가 채워달라고 한 창작 조각은 답변에서 어디를 내가 채웠는지 밝힌다.
- 재미 포인트·네이밍·반전처럼 취향이 갈리는 선택지는 여러 안을 내고 사용자가 고르게 한다.
- md 수정 후에는 반드시 해당 docx를 재생성한다(둘이 어긋난 채 두지 말 것).
- 파일은 덮어쓰지 않고 버전을 올려 저장한다(`_v2`). 어떤 버전이 최종인지 헷갈리지 않게 한다.
