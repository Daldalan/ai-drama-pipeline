## 0-A. 캐릭터 카드 템플릿

```markdown
# <작품명> — 캐릭터 카드 (v1)

## 쾌감 설계
- 이 작품에서 시청자가 보고 싶은 장면: (예: 참교육, 개그)
- 쾌감 축: (예: 힘 / 외모 / 돈 — 주인공마다 하나씩, 겹치지 않게)

| 이름 | 나이 | 쾌감 축 | 능력 | 성격 | 말투 | 트레이드마크 동작 |
|------|------|--------|------|------|------|------------------|
| | | | | | (예시 대사 한 줄) | (반복되는 동작·대사) |

## 외형 메모 (캐릭터 시트 프롬프트용)
- <이름>: 있을 법한 현실적인 얼굴, 헤어, 체형, 기본 의상 (의상이 바뀌는 편은 따로 표기)
```

원칙:
- 쾌감 축이 겹치면 두 인물이 같은 장면에서 같은 역할을 하게 된다. 겹치면 하나를 바꾸자고 제안한다.
- 트레이드마크는 하나만, 짧고 반복 가능한 것으로. 편마다 한 번 이상 쓸 자리를 트리트먼트에서 표시한다.

## 0-B. 시리즈 바이블 템플릿

```markdown
# <작품명> — 시리즈 바이블

> 확정된 설정만 적는다. 미정은 (보류). 마지막 갱신: <날짜>

## 세계관 규칙
- **능력과 대가**: <능력> → <대가> → 그래서 <쓰지 않는 상황>
- **조직**: 이름 / 목적 / 서열
- **금기**: 무엇이 금지되고, 어기면 무슨 일이 생기는가

## 인물 관계
- A ↔ B: 관계 한 줄 (공개 정보 / 숨긴 정보 구분)

## 떡밥·반전 목록
| 떡밥 | 심은 곳 | 회수 예정 아크/에피소드 | 상태 |
|------|--------|----------------------|------|
| | EP02 P3 | 시즌1 후반 | 미회수 |

## 갱신 기록
- <날짜> — <무엇이 어떻게 바뀌었는지> (이전: ...)
```

원칙:
- 규칙에는 "그래서 어떤 장면에서는 쓰지 않는다"까지 적는다. 규칙이 장면 판단 기준이 되게 하기 위해서다.
- 바뀐 설정은 지우지 말고 갱신 기록에 이전 값을 남긴다.

## 1. 트리트먼트 템플릿

```markdown
# <작품명> — 1부 트리트먼트 (v1)

## 로그라인
(2~3문장. "누가 + 어떤 아이러니한 상황에 + 무엇이 문제인지")

## 세계관 / 네이밍
**<핵심 고유명사>: 「이름」**
- 이름의 유래와, 그것이 주제와 어떻게 연결되는지 (이름 자체가 복선이 되게)
- (후보안: A, B, C — 필요하면 교체)

**주인공 이름: <이름> (나이)**
- 이름에 얽힌 말장난/설정
- 성격 요약 (모순되는 두 얼굴이 있으면 코미디가 산다)

## 톤·연출 기준
- 톤: <한 단어 — 긴박함 / 코믹 / 감동 ...>
- 연출 기준(선택): <감독·촬영감독 이름과 참고할 조명·색감> — 이 편의 모든 이미지·영상 프롬프트에 공통 적용

## 1부 씬 구성
### S1. <장면 제목>
- 비트 단위 요약 (웃긴 포인트는 "(웃긴 포인트 ①)" 식으로 태깅)
...

## 5요소 점검
| 요소 | 내용 | 진단 |
|------|------|------|
| 목표 | 주인공이 이 편에서 얻으려는 것 | ✅ / 약함 / 없음 |
| 장애 | 그것을 막는 것 | |
| 전술 | 주인공이 장애를 넘는 방식 (캐릭터다운가) | |
| 반전 | 예상을 뒤집는 지점 | |
| 관객 평가 변화 | 편이 끝났을 때 관객이 인물·상황을 다르게 보게 되는 점 | |
- 설정 충돌: (바이블·캐릭터 카드와 어긋나는 부분, 없으면 "없음")

## 심어둔 떡밥 (2부용)
- 떡밥 하나당 한 줄: 무엇이 미해결인지 + 가능한 회수 방향 후보
```

원칙:
- 사용자 피치의 빈 조각은 직접 창작해 채우되, 답변에서 "내가 짠 부분"이라고 명시한다.
- 네이밍에는 반드시 이유를 단다. 이유 없는 이름은 사용자가 판단할 근거가 없다.
- 웃긴 포인트에는 번호 태그를 달아 사용자가 개별적으로 피드백할 수 있게 한다.
- 5요소 중 "약함/없음"이 있으면 보강안을 2~3개 붙이되, 고치는 건 사용자 선택 후에 한다.

## 1-B. 파트 분할 표

영상 도구 1클립으로 만들 수 있는 길이 단위. 파트 번호는 파일 이름 규칙(`EP05_P2_...`)과 맞춘다.

```markdown
## EP05 <부제> — 파트 분할

| 파트 | 예상 길이 | 장소 | 등장인물 | 핵심 대사 | 마지막 훅 |
|------|---------|------|---------|----------|----------|
| P1 | ~15s | | | "..." | 다음 파트가 궁금해지는 끊김 |
| P2 | ~30s | | | | |

### 파트별 연속성 메모 (같은 장소가 이어질 때)
- P2 시작: 인물 위치·바라보는 방향 / 문·소품 상태 (P1 종료 상태를 이어받음)
- 액션 파트: 준비 → 타격 → 반응 → 여운 (타격 방향과 반응 방향을 맞춘다)
```

원칙:
- 대사가 파트 길이를 넘기면 파트를 나누고 초수를 다시 배분한다. 말을 빠르게 하라고 하지 않는다.
- 파트마다 훅이 없으면 "훅 없음"으로 표시하고 후보를 제안한다.

## 1-C. 재미 포인트 점검표

```markdown
## EP05 재미 포인트 점검

| 편 | 개그 | 감동 | 반전 | 공감 | 참교육 | 비어 있거나 늘어지는 구간 |
|----|-----|-----|-----|-----|-------|------------------------|
| 1편 | ✅ | — | ✅ | — | — | S#3 설명만 이어짐 |

### 구간별 제안 (작가님이 고름)
**1편 S#3 — 감동 비어 있음**
- ① <안> — 근거: <캐릭터/세계관 근거>
- ② <안> — 근거: ...
- ③ <안> — 근거: ...
```

원칙:
- 축은 작품 장르에 맞게 바꿀 수 있다. 다섯 개를 모든 편에 억지로 채우지 않는다 — 비어서 늘어지는 편을 찾는 도구다.
- 제안은 구간마다 3~5안. 고른 뒤에는 바이블·캐릭터 카드와 충돌이 없는지 다시 본다.

## 2. 대본 포맷 상세 (변환기 문법)

`scripts/make_script_docx.js`가 파싱하는 문법. 정확히 지켜야 Word가 예쁘게 나온다.

```markdown
# <작품명> — N부 대본 (vX)          ← 문서 제목 (2번째 #부터 새 페이지)

등장인물:                            ← 지문으로 렌더링됨 (자유 서술)
**이름** (나이, 성별) — 소개          ← 콜론이 없으면 대사가 아닌 지문 처리

---                                  ← 구분선

## S#1. 장소 (시간)                  ← 씬 헤딩

지문은 그냥 쓴다. 현재형. 여러 줄 가능.   ← 회색 이탤릭

**이름:** (지시문) 대사              ← 대사: 콜론이 ** 안에 있어야 함

### [몽타주 — 제목]                  ← 몽타주 헤딩
- 몽타주 항목                        ← 불릿

**— 1부 끝 —**                       ← 부 종료 마커 (가운데 정렬, "— ... —" 형태 필수)

## 심어둔 떡밥 (2부용)                ← 작업 노트: 반드시 종료 마커 "뒤"에
```

주의:
- 대사 판별 정규식은 `**이름:**` — 콜론이 볼드 밖에 있으면(`**이름**: 대사`) 지문으로 처리된다.
- 씬 번호는 부를 넘어 연속 (1부 S#1~9 → 2부 S#10~).
- 인물명에 지시 대상을 붙일 수 있다: `**남자:** (목소리만) ...`
- **떡밥 섹션은 부 종료 마커 뒤에 쓴다.** 통합본 추출 awk가 종료 마커에서 멈추기 때문에, 마커 뒤에 있어야 작업 노트가 통합본에서 자동 제외된다.

## 3. 밈 패러디 가이드

**철칙: 짤 이미지 삽입 금지 (방송사 저작권 + 초상권). 대사·상황 패러디로만.**
짧은 유행어 대사 패러디는 국내 예능/드라마 관행상 안전권이다.

배치 원칙:
- 부당 4~6개로 절제. 밈을 위해 장면을 만들지 말고, 이미 있는 장면의 캐릭터 일관성에 맞는 밈을 고른다.
- 가장 좋은 밈 배치는 **밈이 곧 캐릭터/플롯 장치가 되는 것** (예: "사딸라"를 동화 속 인물이 말하게 해서 현실 출신 떡밥으로 활용).
- 사용자가 짤을 던져주면 그 짤의 대사를 최우선으로 배치한다.

검증된 밈 풀 (출처 — 패러디 예):
- "이 차는 이제 제껍니다. 제 마음대로 팔 수 있는 겁니다" (MBC 뉴스) — 소유권 주장 장면
- "어이가 없네?" (베테랑) — 권위자가 반항에 얼어붙는 리액션
- "내가 왕이 될 상인가" (관상) — 얼굴 평가 장면
- "니가 가라 하와이" (친구) — 떠넘기기 거부
- "누구인가? 누가 기침(웃음)소리를 내었어" (태조왕건 궁예) — 권력자의 색출
- "중요한 건 꺾이지 않는 마음" (2022 유행어) — 비틀어서 신체 개그로
- "사딸라" (야인시대) — 가격 흥정 + 현대인 정체 떡밥
- "실화냐" — 비현실적 상황 리액션
- "묻고 더블로 가" (타짜) — 도박수 장면
- "형(네)이 왜 거기서 나와" (노래) — 의외의 등장

## 4. IP 체크리스트 템플릿

원작이 있는 작품(동화, 고전, 신화 등)일 때 생성. 파일명: `<원작IP>요소_체크리스트.md`

```markdown
# <IP사> 요소 안 씀 — IP 체크리스트

> 원칙: 원작(퍼블릭 도메인)은 자유, 각색자가 "추가한 표현"은 금지.
> 마지막 점검: <날짜> (<대상 문서> 기준)

## 1. 써도 되는 것 (퍼블릭 도메인)
- [x] 원작 스토리·모티프 (원작자, 연도 명기)

## 2. 금지 — 대본 단계
- [ ] ~~각색사 명칭 직접 언급~~ (현재: 없음 ✅)
- [ ] ~~각색사가 창작한 캐릭터·노래·장면~~ (현재: 없음 ✅)

## 3. 금지 — 영상화 단계
- [ ] 각색사 고유 비주얼(의상 색 조합, 건축 실루엣, 로고 서체) 복제 금지
- [ ] AI 이미지 생성 시 "<각색사> 스타일" 프롬프트 금지

## 4. 기타 타사 IP 주의
- [ ] 작품 내 고유명사의 기존 상표 충돌 (상업화 시 상표 검색)
- [ ] 밈/짤: 이미지 삽입 금지, 대사 패러디만

## 5. 배급 전 최종 게이트
- [ ] 법무 검토 / 상표 검색 / AI 비주얼 육안 대조

**한 줄 요약**: 이야기는 원작자 것(공짜), <상징 비주얼>은 각색사 것(금지).
```

새 부를 쓸 때마다 2번 섹션 기준으로 자체 검열하고 "마지막 점검" 날짜를 갱신한다.

## 5. 통합본 구조 + 떡밥 회수표 예시

```markdown
# <작품명> — 통합본 (1~N부 완결)

## 로그라인
## 등장인물 (전체)        ← 정체 반전이 있었으면 공개된 최종 정보로 작성
## 세계 규칙              ← 부마다 흩어진 규칙을 ①~⑤로 통합
## 배경

# 제1부 — <부제>
(1부 씬 구간)
# 제2부 — <부제>
...

# 부록 — 떡밥 회수표
- **<떡밥명>** — 심음: 1부 S#5 (...) → 회수: 3부 S#20 (...)
## 버전 기록
- 1부 v1.1 — ...
```

씬 구간 추출:
```bash
awk '/^## S#/{f=1} f{print} f && /^\*\*— .+ —\*\*$/{exit}' <N부_대본.md>
```

떡밥 회수표는 장식이 아니다 — 이후 씬을 수정할 때 "이 씬이 어떤 떡밥의 심기/회수 지점인지"
확인하는 안전망으로 쓴다. 회수표에 있는 씬을 고치면 반대쪽 지점도 함께 점검한다.
